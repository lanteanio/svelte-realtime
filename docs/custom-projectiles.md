# Custom projectile simulation

Use `hitTest: { resolveShot(ctx, command, timing) { ... } }` as an alternative to `shot`, `hitbox`, `resolve` and `onHit`; do not combine the two modes. The client still calls `view.shoot(command)`, so render-time stamping, acknowledgement measurement, strict-older replay rejection and owner forwarding use the same path. The callback runs once even when no other entity is nearby. `interest` remains required for the server-observed delivery cadence; your callback owns projectile travel, history lookup, map obstruction and contact geometry.

`timing` is a frozen snapshot of millisecond durations: `rewindMs` is the nonnegative view age clamped to `reach` and `maxRewindMs`; missing or future render hints, and an edge without an owner-clock basis, request zero rewind. `reach` is the admitted budget. `minUplink` and `maxUplink` are recent half-round-trip samples (double them for round-trip bounds); `interpDelay` is the server-observed interpolation allowance. These three measurement fields are `null` before a sample is available. Measurement components describe observed cadence; only `rewindMs` is the admitted compensation, and they never authorize extending its cap. The server measures the cadence instead of trusting a client interpolation setting, including level-of-detail and broadcast-rate changes.

Read the shooter's current state through `ctx.state`. Use `ctx.applyTo(key, command)` to enqueue an authoritative command and `ctx.emitEvent(type, data, options?)` for a discrete event. These methods stop working when the callback settles or throws, when its shooter entity is replaced/removed, or when ownership changes. An injected command drains on a later tick; ordinary `apply`, `onMissing` and server-injected continuation receive no reusable timing authority. If a callback throws, its buffered events are discarded, while commands it already enqueued still drain. Capture the bounded compensation when creating a projectile; advance its travel on subsequent ticks without borrowing a later shot's timing. In a cluster, only durations cross the edge/owner hop and the owner reapplies its own cap.

Acknowledgement samples estimate recent round-trip bounds from echoed server times within the existing acceptance window. They are not proof of physical one-way latency; the admitted compensation cap remains the security boundary.
